# Image signing demo

Self-signed PKI and a minimal werf project for testing delivery-kit image
manifest signing (`--sign-manifest`).

> The keys are throwaway demo keys generated by `gen-keys.sh`. They are **not**
> committed — run the script to produce them locally.

## What's here

| Path | Purpose |
| --- | --- |
| `werf.yaml` | Minimal werf project (`alpine:3.20`) |
| `gen-keys.sh` | Generates the whole chain and `sign.env` |
| `wrap-key/` | Tiny Go tool: plain PKCS#8 key → sigstore-encrypted PEM |

After running `gen-keys.sh` you also get (gitignored):

| File | Maps to |
| --- | --- |
| `root.key` / `root.crt` | Self-signed root CA (`root.crt` → `WERF_VERIFY_ROOTS`) |
| `intermediate.key` / `.crt` | Sub-CA signed by root (`.crt` → `WERF_SIGN_INTERMEDIATES`) |
| `leaf.key` / `leaf.crt` | Leaf signer cert (`leaf.crt` → `WERF_SIGN_CERT`) |
| `leaf.enc.key` | Sigstore-encrypted `leaf.key` → `WERF_SIGN_KEY` |
| `chain.crt` | `intermediate + root` (root last), for reference |
| `sign.env` | Ready-to-source env vars |

All keys are ECDSA P256. Chain: **root → intermediate → leaf**.

## The one gotcha: the key format

`WERF_SIGN_KEY` is **not** a plain openssl key. delivery-kit always runs
sigstore's `encrypted.Decrypt` on the key bytes, so the key must be a PKCS#8
private key wrapped in the sigstore `encrypted` format with PEM type
`ENCRYPTED DELIVERY-KIT PRIVATE KEY` (empty passphrase, matching
`SkipPassword`).

`gen-keys.sh` produces this as `leaf.enc.key` via `wrap-key/`. A bare
`openssl genpkey` output fails with
`decrypt: invalid character ... after top-level value`.

## Generate the keys

```bash
cd playground/signing
./gen-keys.sh        # needs openssl + Go
```

## Build + sign

You need a built delivery-kit binary and a registry to push to.

```bash
# 1) Build the binary
export TASK_X_REMOTE_TASKFILES=1
task build                           # -> ./bin/werf

# 2) A local registry
docker run -d -p 5001:5000 --name registry registry:2

# 3) Build + sign (sign.env resolves paths relative to itself)
#    --dev lets werf read this sub-project from disk without committing
cd playground/signing
source ./sign.env
../../bin/werf build --dev \
  --repo localhost:5001/dk-sign-test \
  --sign-manifest \
  --sign-key  "$WERF_SIGN_KEY" \
  --sign-cert "$WERF_SIGN_CERT" \
  --sign-intermediates "$WERF_SIGN_INTERMEDIATES" \
  --annotate-layers-with-dm-verity-root-hash \
  --save-build-report --build-report-path /tmp/dk-report.json
```

A successful run shows a `Building stage app/sign` step. The pushed manifest
carries the signature bundle annotations:

```bash
REF=$(jq -r '.Images | to_entries[0].value.DockerImageName' /tmp/dk-report.json)
crane manifest "$REF" | jq -r '.annotations | keys[] | select(contains("delivery-kit"))'
# io.deckhouse.delivery-kit.signature
# io.deckhouse.delivery-kit.cert
# io.deckhouse.delivery-kit.chain
```

## Verify

```bash
../../bin/werf verify \
  --image-ref "$REF" \
  --verify-manifest \
  --verify-roots "$WERF_VERIFY_ROOTS"
# └ Verifying image (1/1)
#   │ Manifest signature ... ok
```
