# Contracts: os-pm File-Based Syntax

## Contract 1: `werf.yaml` Configuration Schema

### Package Directive Syntax

The `os-pm` type uses file-based syntax only. Inline spec lists are rejected.

```yaml
packages:
  - type: os-pm
    # spec: string (optional, defaults to "pm.yaml")
    # lock: string (optional, defaults to "pm.lock")
    # workdir: not accepted (validation error)
    # env: map[string]string (optional, passed as env var prefix)
```

### Examples

**Minimal** (default spec and lock at repo root):
```yaml
packages:
  - type: os-pm
```

**Custom file paths**:
```yaml
packages:
  - type: os-pm
    spec: custom-pm.yaml
    lock: custom.lock
```

**With environment variables** (as established in `012-os-pm-env-vars`):
```yaml
packages:
  - type: os-pm
    env:
      HTTP_PROXY: "http://proxy.example.com:8080"
```

**With stageDependencies** (user-side configuration):
```yaml
git:
  - stageDependencies:
      packages:
        - pm.yaml
        - pm.lock
```

### Rejected Configurations

- `spec: [curl, jq]` → Config parse error: "spec must be a string"
- `workdir: /app` → Config parse error: "workdir is not supported for type os-pm"

## Contract 2: File Conventions

### `pm.yaml` (Spec File)

- Location: Repository root (no `workdir` prefix)
- Content: Package spec authored by user in pm format
- Committed to Git: Yes
- Managed by: User (manually edited or via `pm` tool)
- File existence: Required for build

### `pm.lock` (Lock File)

- Location: Repository root (no `workdir` prefix)
- Content: Deterministic lock file generated by `pm lock`
- Committed to Git: Yes
- Managed by: User (generated by `pm lock`, committed manually)
- File existence: Required for build. If missing when `pm.yaml` exists → build fails with clear error

## Contract 3: Build Command Generation

### Generated Shell Command Structure

```
<mkdir -p /var/lib/pm> ; <container-factory-version snapshot> ; <env prefix> <secret resolution> pm sync --from <lockfile>
```

Where:
- **mkdir**: Creates `/var/lib/pm` directory
- **Container factory version snapshot**: Reads `PACKAGES_VERSION` (from secret or env) and writes to `/var/lib/pm/container-factory-version`
- **Env prefix**: User-specified env vars from `packages.env`
- **Secret resolution**: Inline shell expansion for `PACKAGES_VERSION` and `REGISTRY` secrets
- **pm sync command**: `pm sync --from <lockfile>` with lock file path relative to repo root

### Before/After Comparison

| Aspect | Before (inline) | After (file-based) |
|--------|-----------------|-------------------|
| Command | `pm install curl jq` | `pm sync --from pm.lock` |
| Spec | Inline list `[curl, jq]` | File `pm.yaml` |
| Lock | N/A | File `pm.lock` |
| Container version snapshot | Present | Preserved |
| Env vars | Supported | Supported |
| Workdir | Implicitly absent | Explicitly rejected |

## Contract 4: SBOM Integration

### Cataloger Registration

- **CatalogerName**: `"os-pm-lock-cataloger"`
- **Source paths scanned**: `pm.yaml`, `pm.lock` (at repo root, no workdir prefix)
- **Filter mode**: `CatalogerFilterExactPath`
- **Scan location**: Build context (host filesystem / Git repository), NOT inside the built image

### SBOM Contract

- All component metadata (names, versions, licenses, dependencies) extracted from `pm.lock` in the build context
- The `container-factory-version` file at `/var/lib/pm/container-factory-version` (inside the container) provides the factory version for purl generation
- The SBOM output includes components filtered to match the cataloger's source paths
